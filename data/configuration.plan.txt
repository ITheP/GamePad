Config should be displayed as follows...
- To keep it simple, display as a table with the following columns
    - Name (from Metadata.Label)
    - Description (from Metadata.Description) with info from Metadata.Info displayed in a smaller font below it
    - Value (from Metadata.Value)
- each config should be grouped by the group value with the group value used as a group heading

each value should be formatted as follows...
- for boolean, if RenderAs is Toggle then display as a toggle switch, if RenderAs is checkbox then display as a checkbox/switch that toggles the value on/off. Any other renderas treat as a cheapbox
- for int, render as a slider with the uimin/uimax/uistep values from the metadata as the range, and the current value displayed in a text box next to it. The text box should be editable and when edited, the slider should update to match it. Allow values in  text box to be entered to the min and max values; Under the slider it should list the min/max values
- For float, render as a slider with the uimin/uimax/uistep values from the metadata as the range, and the current value displayed in a text box next to it. The text box should be editable and when edited, the slider should update to match it. Allow values in  text box to be entered to the min and max values; Under the slider it should list the min/max values
- for string, render as a text box with the current value displayed in it. The text box should be editable. min/max represent minimum and maximum length string allowed. Text under text box should list min and max length allowed.

- to the left of the values, should be a little default button which if pressed applies the default value.

- When saving a setting, this involves involves calling POST_UpdateConfig passing the id of the config and the value to set. Don't forget to make any values json safe.
- When applying, a little save icon should appear next to it as it saves.
- checks should be made on the return state. If it is ok, then great show a tick that fades over 2 seconds.
- Otherwise save may have failed - it may have failed to reach the controller, timed out, or the controller may have rejected the value. etc.
- In either case, the config will not have been applied. An error icon should display next to the control, with a retry button that retries if pressed (back to save icon etc.)
- On success will also hide the error and retry button if they were showing.
- Applying a boolean operation can be done straight away, no need to click as save button. Should still have the same save, retry etc.

- Javascript used should include existing .css and any new css for the inputs should be under an isolated Input class (or parent div)
- All the rendered controls should be done using reusable code so define once, then the loop that generates the controls etc.
- There should be a refresh all button at the top that re-reads and re-displays everything (incase somethings changed on the device in the background).

- You can use main.js as an example of the style of javascript for handling this.
- configuration.html already contains the wrapper you need for the content (it is embedded elsewhere so you don't need the header, body etc.. - that is already taken care of, just concentrate on the table with extra content between the <p>Configuration</p> and table tags)
- existing css is defined in default.css please make any new css in configuration.css and include that in configuration.html

- use the following for icons: Failed ❌, Save 💾, Saving ⏳, Default 🅾️, Retry 🔄, Warning ⚠️ (e.g. out of range), Information ℹ️
